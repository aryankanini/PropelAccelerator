# User Story - US_003

## Story ID
US_003

## Story Title
Configure Durable Job Delivery

## Status
- **State**: Draft
- **Superseded By**: N/A
- **Change Request**: N/A

## Description
As an operations engineer, I want durable asynchronous job delivery so that processing retries do not create duplicate compliance work.

## Acceptance Criteria

### AC-001: Process an idempotent job
- **Given**: A processing command with a stable processing-record and job-attempt identity
- **When**: Service Bus delivers the command more than once
- **Then**: The worker records one logical processing outcome for that identity
- **And**: Duplicate delivery is observable in the job record

### AC-002: Handle exhausted retries
- **Given**: A retryable worker failure
- **When**: The configured bounded retry count is exhausted
- **Then**: The command is dead-lettered with its correlation identifier and failure reason

## Edge Cases
- A malformed message is rejected without being executed and is routed to the dead-letter path with a validation failure reason.
